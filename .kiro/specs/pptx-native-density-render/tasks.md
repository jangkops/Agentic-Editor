# Implementation Plan: pptx-native-density-render

## Overview

`slide_templates`의 알려진_레이아웃을 1920×1080 PNG로 굽지 않고 편집가능 네이티브 PPTX 도형으로 직접 렌더하는 신규 경로를 만든다. 신규 모듈 `ai_engine/native_layout_renderer.py`가 콘텐츠를 네이티브 도형으로 방출하고, `layout_geometry`로 겹침<10%·경계 안·제목 1회를 구조적으로 보장하며, `server.py`의 렌더 결정 게이트가 콘텐츠 베이크 대신 네이티브 라우팅으로 전환한다. 합격 기준은 hermetic 단위 테스트가 아니라 실제 생성된 .pptx를 audit하는 신규 산출물_검증기 `scripts/audit_pptx_native_density.py`의 (a)~(h) 통합 게이트 + 선행 스펙 회귀 0이다.

구현 언어는 design 전반(python-pptx, Hypothesis)에 따라 **Python**으로 한다.

### 실행 규약 (전 작업 공통)

- 모든 테스트는 **파일로 작성**하고 단발 실행한다. 인라인 멀티라인 `python -c` 금지, heredoc/stdin 금지, watch 모드 금지.
  - 실행: `./venv/bin/python -m pytest <test_file> -p no:cacheprovider -q`
- PBT는 **Hypothesis** 사용(직접 구현 금지), 각 Correctness Property는 **단일 테스트**로 구현하고 `@settings(max_examples=100)` 이상.
  - 각 PBT 파일/테스트에 태그 주석: `# Feature: pptx-native-density-render, Property {N}: {property_text}`
- PBT/단위는 **네트워크 0**: 게이트웨이·Vertex 실호출 없이 mock. 실제 Vertex는 옵트인 통합에서만(`AE_ENABLE_VERTEX_IMAGE=1`).
- **Chrome 불필요(자동판정)**: 네이티브 경로는 HTML→PNG 래스터화를 거치지 않으므로 .pptx 생성·audit이 python-pptx만으로 동작. `visual_comparator`(Chrome 헤드리스)는 육안 보조 산출물이며 미가용/타임아웃(20초+ hang 방지) 시 skip 가능하고 자동판정에 영향 없음.
- `server.py` 수정은 **디스크 상태 기준** 패치(에디터 버퍼 STALE 가능) — grep으로 앵커 유일성 검증 후 **가산적·바이트 보존**으로 적용, 비결함 입력은 no-op.
- LLM/operation JSON 생성은 Bedrock_게이트웨이 경유만, 이미지 생성은 `ai_engine/vertex_image_module.py` 단일 모듈만(gateway.md/security.md 정합).
