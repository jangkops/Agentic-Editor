# 요구사항: 모델 추천 (Model Recommend) 기능

## 개요
사용자가 현재 선택된 모델로 특정 작업(이미지 생성, PDF 생성, 코드 분석 등)을 요청했을 때, 해당 모델이 그 작업에 적합하지 않으면 채팅창에 추천 모델 3개를 버튼으로 표시하여 사용자가 클릭으로 선택 후 자동 재실행되게 하는 기능.

## 핵심 시나리오
1. 사용자가 Gemma 3 4B (tool-use 미지원)로 "이미지 생성해줘" 요청
2. 에이전트가 도구 호출 실패 또는 텍스트만 반환
3. 채팅창에 "이 작업에 더 적합한 모델을 추천합니다" 메시지 + 3개 버튼 표시
4. 사용자가 버튼 클릭 → 모델 자동 전환 + 동일 프롬프트 재실행

## 요구사항

### 1. 작업 유형 감지
- 사용자 프롬프트에서 작업 유형 분류: image_gen, pdf_gen, pptx_gen, code_analysis, general_chat
- 키워드 기반 + 간단한 패턴 매칭 (LLM 호출 없이 클라이언트 측에서 즉시 판단)

### 2. 모델 적합성 판단
- 각 모델의 capability matrix 활용 (이미 server.py에 _AGENT_CAPABLE_PREFIXES 등 존재)
- tool-use 필요 작업인데 현재 모델이 tool-use 미지원 → 추천 트리거
- 이미지 생성 요청인데 현재 모델이 agent 미지원 → 추천 트리거

### 3. 추천 모델 선정 기준
- 작업 유형에 맞는 capability 보유
- 비용 효율 순 (저렴한 것 우선)
- 응답 속도 순 (빠른 것 우선)
- 최대 3개 추천

### 4. UI 표시
- 채팅창에 시스템 메시지로 표시 (Kiro의 옵션 버튼 스타일)
- 각 버튼: 모델명 + 간단한 설명 (예: "Claude Haiku 4.5 — 빠르고 정확한 도구 실행")
- 버튼 클릭 시:
  - 모델 셀렉터 자동 전환
  - 동일 프롬프트로 재실행
  - 추천 메시지는 접힘 처리

### 5. 트리거 조건
- 에이전트 루프에서 도구 호출 없이 텍스트만 반환된 경우
- 또는 tool_unsupported_fallback이 발동된 경우
- 또는 프론트엔드에서 사전 감지 (모델 capability 캐시 기반)

### 6. 사전 감지 (선호)
- 프론트엔드가 `/api/models` 응답의 capability 정보를 캐시
- 사용자가 메시지 전송 시 프롬프트 분석 → 현재 모델 capability 비교
- 부적합하면 **전송 전에** 추천 표시 (더 좋은 UX)
- 사용자가 "그래도 진행" 선택 가능

## 비기능 요구사항
- 추천 로직은 클라이언트 측에서 실행 (서버 호출 없이 즉시)
- 모델 capability 캐시는 앱 시작 시 1회 로드 + 1시간 TTL
- 추천 UI는 VS Code 다크 테마에 맞는 스타일
- 추천 버튼은 Web Component가 아닌 인라인 HTML (채팅 메시지 안에 렌더)
