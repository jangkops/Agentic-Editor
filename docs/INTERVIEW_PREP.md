## 1. 자기소개 (1분 / 2분 버전)

### 1분 버전

안녕하세요, 4년차 클라우드/플랫폼 엔지니어 장창근입니다.

현재 GC녹십자 목암생명과학연구소에서 AWS Bedrock 기반 멀티모델 AI 에이전트 에디터를 직접 설계하고 개발하고 있습니다. 70개 이상의 LLM 모델을 병렬 호출하고, 합의를 도출하며, RAG로 프로젝트 코드를 인식하는 데스크톱 애플리케이션을 Python FastAPI + Electron으로 구현했습니다.

특히 LLM이 파일 읽기/쓰기, 명령 실행, 검색 등 5개 도구를 자율적으로 사용하는 에이전트 루프를 직접 구현한 경험이 있어, 키움저축은행의 AI 에이전트 개발 및 사내 AI 활용 지원 업무에 즉시 기여할 수 있다고 확신합니다.

### 2분 버전 (위 + 아래 추가)

인프라 엔지니어로 시작해 CI/CD 파이프라인, Kubernetes 운영, Terraform IaC를 거쳐 현재는 AI 에이전트 개발에 집중하고 있습니다. 이 과정에서 "운영 자동화"라는 일관된 방향성을 유지해왔고, 그 연장선에서 LLM 기반 자동화 도구를 직접 만들게 되었습니다.

Bedrock Gateway의 쿼터 관리 파이프라인을 Terraform으로 구축하고, 사용자별 비용 추적 시스템을 React + Python으로 개발한 경험도 있어, 금융권의 비용 통제와 거버넌스 요구사항을 잘 이해하고 있습니다.

## 2. 지원동기

키움저축은행에 지원한 이유는 세 가지입니다.

**첫째, AI 에이전트를 "실제 업무"에 적용하는 경험을 하고 싶습니다.**
현재 제가 만든 에이전트 에디터는 개발자 도구입니다. 하지만 금융 도메인에서 AI 에이전트가 심사, 고객 응대, 문서 처리 등 비즈니스 프로세스를 자동화하는 것은 훨씬 더 큰 임팩트입니다. 제가 가진 에이전트 아키텍처 설계 역량을 금융 비즈니스에 적용해보고 싶습니다.

**둘째, 공고의 기술 스택이 제 현재 업무와 정확히 일치합니다.**
Python 데이터 처리/API 연동, AI 코딩 도구 활용, LangGraph/LangChain 오케스트레이션, 멀티에이전트 워크플로우 설계 — 이 모든 것을 현재 프로젝트에서 실무로 수행하고 있습니다.

**셋째, 사내 교육/가이드 문서 작성 경험이 있습니다.**
엑셈에서 Kubernetes/Docker 본부 대상 교육자료를 제작하고, Helm Chart 가이드를 작성해 개발팀에 전파한 경험이 있어, 사내 AI 활용 지원 업무에도 자연스럽게 기여할 수 있습니다.

## 4. 핵심 프로젝트 설명 (기술면접용)

### 프로젝트: Agentic Editor (AI 멀티모델 에이전트 에디터)

**한 줄 요약**: 70+ LLM 모델을 단일/병렬로 호출하고, 합의를 도출하며, 프로젝트 코드를 인식하는 데스크톱 AI 코드 에디터.

**아키텍처**:
```
Electron (Frontend) ←→ FastAPI (Backend) ←→ AWS Bedrock Gateway (Lambda Function URL)
     │                       │
     │                  ┌────┴────┐
     │                  │ RAG     │ ← TF-IDF + BM25 하이브리드 검색
     │                  │ Memory  │ ← 요약 체크포인트 (Haiku)
     │                  │ Agent   │ ← 5개 도구 자율 사용 (최대 10턴)
     │                  └─────────┘
     │
     └── Monaco Editor + 파일 탐색기 + Git + 터미널
```

**핵심 기술 결정과 이유**:

1. **왜 Bedrock Gateway인가?**
   - 직접 Bedrock Runtime 호출 대신 Gateway를 거치는 이유: 사용자별 쿼터 관리, 비용 추적, rate limiting
   - SigV4 서명 + Lambda Function URL로 실시간 SSE 스트리밍

2. **왜 TF-IDF 로컬 임베딩인가? (Bedrock Titan 대신)**
   - BedrockUser IAM Role은 Gateway /converse만 호출 가능 (임베딩 API 권한 없음)
   - scikit-learn TF-IDF로 로컬 처리 → API 호출 비용 0, 지연 0
   - numpy VectorStore로 코사인 유사도 검색 (.npy 파일 영속화)

3. **왜 하이브리드 검색인가?**
   - 벡터만: 의미는 잡지만 정확한 함수명/변수명 검색 약함
   - BM25만: 키워드는 잡지만 의미적 유사도 못 잡음
   - 결합 (60% 벡터 + 40% BM25): 두 장점 모두 확보

4. **에이전트 도구 루프 설계**:
   - LLM이 `tool_use` stop reason으로 응답 → 서버가 도구 실행 → 결과를 `toolResult`로 재주입 → 최대 10턴 반복
   - 5개 도구: read_file, write_file, list_directory, run_command, search_files
   - 도구 실행은 `asyncio.to_thread`로 비동기 처리 (이벤트 루프 블로킹 방지)

5. **대화 메모리 (요약 체크포인트)**:
   - 12개 이상 메시지 누적 시 Haiku 모델로 자동 요약
   - `[요약 체크포인트] + [최근 10개 원본] + [현재 질문]` 구조
   - Bedrock user/assistant 교대 규칙 자동 정리

## 5. 기술면접 예상 질문 & 답변

### Q1. AI 에이전트의 아키텍처를 설명해주세요.

**답변**: 제가 구현한 에이전트는 ReAct(Reasoning + Acting) 패턴을 따릅니다.

1. 사용자 질문 + 시스템 프롬프트(RAG 컨텍스트 포함) + 도구 정의를 LLM에 전달
2. LLM이 텍스트 응답 또는 tool_use 블록으로 응답
3. tool_use면 서버가 해당 도구를 실행하고 결과를 toolResult로 다시 LLM에 전달
4. LLM이 최종 텍스트 응답을 줄 때까지 반복 (최대 10턴)

이 루프를 SSE 스트리밍으로 실시간 전달하여 사용자가 도구 실행 과정을 실시간으로 볼 수 있습니다.

### Q2. LangGraph를 어떻게 활용했나요?

**답변**: 프로젝트에 `ai_engine/agent_system/agent_graph.py`로 LangGraph 기반 멀티에이전트 구조를 설계했습니다. 현재는 단일 에이전트 + 도구 루프가 메인이지만, 향후 Planner → Worker → Reviewer 3단 구조로 확장할 수 있도록 상태 그래프를 미리 정의해두었습니다.

실제로 병렬 호출 → 합의 도출 워크플로우가 이미 멀티에이전트 패턴입니다:
- Worker 에이전트: 여러 모델이 동시에 답변 생성
- Reviewer 에이전트: 합의 모델이 모든 답변을 분석하여 최종 결론 도출

### Q3. RAG 파이프라인을 설명해주세요.

**답변**:
1. **인덱싱**: 프로젝트 파일을 함수/클래스 경계로 스마트 청킹 (60줄 단위, 10줄 오버랩)
2. **임베딩**: scikit-learn TF-IDF Vectorizer (1024차원, sublinear_tf)
3. **검색**: 하이브리드 — 벡터 코사인 유사도(60%) + BM25(40%)
4. **주입**: 상위 8개 청크를 시스템 프롬프트에 삽입 + 파일 트리 + 현재 열린 파일 정보

코드 관련 질문에만 RAG를 적용하고, 일반 질문은 스킵하는 판별 로직도 있습니다.

### Q4. Python으로 API 연동한 경험을 구체적으로 설명해주세요.

**답변**: Agentic Editor의 백엔드 전체가 Python FastAPI입니다.

- **httpx 비동기 클라이언트**: Lambda Function URL에 SigV4 서명된 POST 요청 → SSE 스트리밍 수신
- **botocore SigV4Auth**: AWS API Gateway 인증을 위한 요청 서명
- **boto3 STS assume_role**: BedrockUser IAM Role 자격증명 획득
- **FastAPI StreamingResponse**: async generator로 SSE 이벤트를 클라이언트에 실시간 중계

또한 비용 대시보드에서는 AWS Athena API를 Python으로 호출하여 CUR 데이터를 쿼리하고, React 프론트엔드에 REST API로 제공합니다.

### Q5. 멀티에이전트 워크플로우 자동화 경험을 설명해주세요.

**답변**: 병렬 호출 → 합의 도출 → 단일 모델 이어가기 전체 워크플로우를 설계했습니다.

1. **병렬 호출**: 사용자 질문을 N개 모델에 동시 전송 (각 모델에 chatHistory + RAG 컨텍스트 포함)
2. **합의 도출**: 고차원 모델(Opus)이 모든 답변을 분석 — 사용자 원래 질문, 대화 맥락, 열린 파일, 활성 스킬을 모두 반영
3. **모드 전환**: 합의 카드 하단 "이 모델로 계속 대화" 버튼으로 단일 모드 자동 전환
4. **맥락 유지**: 병렬 합본은 hiddenInChat으로 UI에 숨기되 chatHistory에는 포함 → 다음 턴에서 맥락 유지

### Q6. 금융 도메인에서 AI 에이전트를 어떻게 활용할 수 있다고 생각하나요?

**답변**: 세 가지 방향을 생각합니다.

1. **문서 처리 자동화**: 대출 심사 서류를 에이전트가 읽고 → 필요 정보 추출 → 규정 체크 → 결과 요약. 도구로 OCR, DB 조회, 규정 검색을 사용.
2. **고객 응대 에이전트**: FAQ를 넘어 실제 계좌 조회, 이체 한도 변경 등 액션을 수행하는 에이전트. 금융 규정 준수를 위한 가드레일 필수.
3. **내부 업무 자동화**: 반복적인 보고서 생성, 데이터 집계, 이상 거래 탐지 알림 등을 에이전트가 자율적으로 수행.

제가 구현한 에이전트 도구 루프 패턴이 그대로 적용됩니다 — LLM이 판단하고, 도구가 실행하고, 결과를 다시 LLM이 해석하는 구조.

### Q7. Streamlit/Gradio 대신 왜 Electron + FastAPI를 선택했나요?

**답변**: 목적이 달랐습니다.

- Streamlit/Gradio: 빠른 프로토타이핑, 데이터 시각화에 적합
- Electron + FastAPI: 파일 시스템 접근, 터미널 통합, Git 연동 등 OS 레벨 기능이 필요한 데스크톱 앱

다만 사내 도구 제작 관점에서는 Streamlit이 더 적합한 경우가 많습니다. 비용 대시보드나 계정 관리 포털은 React로 만들었지만, 빠른 PoC가 필요하면 Streamlit으로 먼저 만들고 검증 후 프로덕션화하는 접근을 선호합니다.

### Q8. SSE 스트리밍에서 겪은 문제와 해결 방법은?

**답변**: `ERR_INCOMPLETE_CHUNKED_ENCODING` 문제를 겪었습니다.

**원인**: uvicorn `--reload` 모드에서 파일 수정 시 서버가 리로드되면 진행 중인 SSE 스트림이 강제 종료됨.

**해결**:
1. `--reload-dir ai_engine`으로 감시 범위 제한 (프론트엔드 수정은 서버에 영향 없음)
2. `agent_stream` 제너레이터에 `try/except/finally` + `done_sent` 플래그로 `[DONE]` 이벤트 보장
3. httpx에 `read=120s` 타임아웃 추가 (Lambda 무응답 빠른 감지)
4. 클라이언트에 60초 idle timeout (`_readWithIdleTimeout`) — 서버 끊김 시 UI 자동 복구

### Q9. 비용 관리/쿼터 시스템을 어떻게 구현했나요?

**답변**: Bedrock Gateway 자체에 사용자별 쿼터가 내장되어 있고, 제가 추가로 구현한 것은:

1. **실시간 쿼터 바**: 매 요청 후 Gateway가 반환하는 `remaining_quota_krw`를 UI에 표시
2. **비용 대시보드**: AWS CUR → S3 → Glue 카탈로그 → Athena 쿼리 → React 시각화
3. **프로젝트별 정산**: 태그 기반으로 GPU 인스턴스 비용을 프로젝트별로 분리 (0.3% 오차 미만)
4. **승인 밴드**: 일정 금액 초과 시 StepFunction → SES 알림 → 관리자 승인 후 쿼터 확장

### Q10. checkpoint/restore 기능을 설명해주세요.

**답변**: Kiro(AWS의 AI IDE)에서 영감을 받아 구현했습니다.

- 에이전트가 파일을 수정하기 전에 자동으로 `git stash push --include-untracked`
- 작업 완료 후 "되돌리기" 버튼 표시
- 클릭 시 `git stash pop`으로 에이전트 작업 전 상태 복원
- dirty 상태가 아니면 stash 스킵 (불필요한 checkpoint 방지)

금융권에서는 이런 "되돌리기" 기능이 특히 중요합니다 — AI가 생성한 코드/문서를 검증 전에 적용했다가 문제가 생기면 즉시 원복할 수 있어야 하니까요.

## 7. 약점 대비 (예상 꼬리질문)

### "금융 도메인 경험이 없는데?"

→ 롯데손해보험에서 1년간 금융권 인프라를 운영했습니다. 금융감독원 감사 대비 로그 시스템을 구축하고, DR 훈련을 표준화한 경험이 있어 금융권의 규제 환경과 보안 요구사항을 이해하고 있습니다.

### "Streamlit/Gradio 경험이 직접적으로 없는데?"

→ React + Python Flask로 동일한 목적의 내부 도구를 여러 개 만들었습니다 (비용 대시보드, 계정관리 포털). Streamlit은 더 빠른 프로토타이핑 도구이므로 학습 곡선이 낮고, 필요하면 즉시 전환 가능합니다. 핵심은 "내부 도구를 만들어 업무를 자동화한 경험"이고, 그건 충분합니다.

### "AI 모델을 직접 학습시킨 경험은?"

→ 모델 학습보다는 모델 활용/오케스트레이션에 집중해왔습니다. 70+ 모델을 병렬로 호출하고 합의를 도출하는 시스템, RAG로 도메인 지식을 주입하는 파이프라인, 에이전트 도구 루프 설계가 제 강점입니다. 이 공고도 "AI 에이전트 개발"이지 "AI 모델 학습"이 아니라고 이해했습니다.

### "왜 이직하려고 하나요?"

→ 현재 GC녹십자에서 AI 인프라와 에이전트 개발을 모두 하고 있지만, 인프라 업무 비중이 높습니다. AI 에이전트 개발에 100% 집중할 수 있는 환경을 찾고 있고, 특히 금융 도메인에서 실제 비즈니스 프로세스를 자동화하는 경험을 하고 싶습니다.
